## 三个必须说清楚的结论

1. **换尺子必须重扫阈值，这是实测不是理论。** 同一套代码、同一批题，阈值 0.35 在 bge-m3 下拒答正确率是 **0/7**——因为真向量把分数整体抬到 0.48–0.82，"0.35 以下算无关"这个前提直接失效。旧阈值在新尺子下等于"从不拒答"。
2. **取中点 0.64，不贴边 0.65。** 0.65 也能做到 7/7 拒答，但会误拒 1/17——贴边等于把一题的余量用光。0.64 是唯一两个方向都满分的切点。
3. **延迟是真代价。** 每次查询都要一次远程 HTTP，248 ms vs 哈希 290 µs。上线要么加查询向量缓存（同一问题重复率高），要么本地部署模型，要么接受这个量级。

## 这份成绩的边界（面试要主动说，别等对方问）

- **0.02 的间隙太窄**：该拒最高 0.63、该答最低 0.65，中间只有 0.02。这是 24 题定出来的阈值，不是统计结论；扩样本后必须复扫。
- **7 道该拒题都是"明显离题"**（问公司理赔率、友商比价、免责条款原文），没有"半相关"题（语料里只提一句那种）。真实流量最难的是半相关，这批题没考核到。
- **hit@3 100% 有同源偏差**：题目和语料是同一个人写的，措辞同源。真实用户问法与语料措辞不一致时命中率会掉。
- **30 条语料**：规模小到任何一题的变化都会让百分比跳动 6 个百分点。

## 一致性（判据：换存储不能换语义）

| 检查 | 结果 |
| --- | --- |
| top1 chunk_id 逐题对比（17 题） | **17/17 一致** |
| hit@3 | memory **17/17** / pgvector **17/17** |
| top1 分数最大偏差 | **1.6e-3** |

分数不是 0 差：pgvector 的 `vector` 列是 `float4`（单精度），Python 侧是 `float64`，1.6e-3 是精度截断的必然结果，不是算法差异。**注意**：阈值 0.64 与两侧 0.63 / 0.65 的间距是 0.01，1.6e-3 的误差仍在安全范围内；但若哪天阈值定在两个集群只差 1e-3，就会出现"同一句话换存储后答/不答翻转"。

## 延迟（要拆开看，别把 HTTP 算成数据库）

| 口径 | memory | pgvector |
| --- | --- | --- |
| 端到端单次检索（含远程 embedding） | 198 ms | 207 ms |
| 纯存储（向量已算好，hash 256 维，200 次中位） | 281 µs | 314 µs |
| 纯存储最慢一次 | 399 µs | 4110 µs |

三个结论：

1. **端到端的 200 ms 全是 bge-m3 的 HTTP，不是数据库。** 两者差 8 ms，就是本地 socket + SQL 解析的开销。
2. **30 条语料下两种后端同量级**（281 vs 314 µs）。这个规模内存扫本来就快，pgvector 赢不了。
3. **pgvector 的价值在规模，不在当下**：内存是全表 O(N)，HNSW 是近似 O(log N)；再加上持久化、租户过滤下推到 SQL、多进程共享一份索引。
